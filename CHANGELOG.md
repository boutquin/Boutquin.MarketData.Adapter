## [2.0.0-rc.20261027.4] — 2026-10-27

- CORRA selects the actual Valet rate series `AVG.INTWO` through explicit `CorraSeriesCode`; Bank of Canada FX/CORRA coverage uses the Canadian statutory calendar. Primary payload and publication-date regressions cover the correction.

### 2.0 release candidate

- Use published MarketData `2.0.0-rc.20261027.4` and signed Storage `2.0.0` packages from NuGet.org, pinned by source and hash. Qualify cold Linux, macOS and Windows builds and package-only consumers before publishing frozen archives.
- **Breaking:** credential-bearing Tiingo, TwelveData and FRED endpoints require an absolute HTTPS base URL. All adapter cancellation exceptions propagate instead of being converted to partial data; callers should handle cancellation separately from data-quality failures.
- **Breaking:** price adapters and Frankfurter FX require one symbol/pair per direct request because flat canonical records cannot retain multiple owners. Partition batches in the kernel. Unsupported direct requests fail before I/O.
- Validate provider identity, clip observations to request bounds, select Bank of Canada curve rows chronologically within the lookback, and avoid false no-data errors for expected empty publication days.
- Request unadjusted TwelveData prices explicitly; keep its `AdjustedClose = Close` limitation visible. Tiingo metadata no longer mislabels earliest price history as instrument inception.
- Sanitize public failure messages and FRED provenance URLs. Bound Fama-French decompression, stop at CSV table boundaries, reject malformed ECB CSV and Treasury DTDs, and skip irrelevant CME files before I/O.
- Preserve custom keyed calendar overrides. Adapter-built calendars carry explicit 2020–2030 bounds and warn outside them; SOFR and Treasury use their respective publication calendars.


### Added

- `TiingoDividendHistoryAdapter` fetches cash distributions as `DividendPayment` records by ex-date for US equity and ETF symbols through `DividendHistoryRequest`; it preserves Tiingo's unclassified payment type rather than inferring tax treatment.

### Changed — BREAKING

- `TwelveDataPriceBarAdapter` and `TwelveDataInstrumentMetadataAdapter` now reference `ExchangeCode.XTSE` (Toronto, per the 1.1.0 `Boutquin.MarketData.Abstractions` rename) in place of the old `ExchangeCode.XTOR` in their supported-exchange sets. Behaviourally equivalent — both names identified Toronto Stock Exchange in their respective enum generations — but a rebuild against the 2.0 RC Abstractions package is required for any in-source adapter fork.
- `TwelveDataInstrumentMetadataAdapter` now calls TwelveData's `/etfs` endpoint instead of `/stocks`. The `/stocks` endpoint returns only common-stock listings and silently filters out ETFs — the root cause of the 2026-04-19 CA research regression where a bare <c>XIC</c> request returned "Scandinavian Energies Inc." (an unrelated German stock sharing the 3-letter symbol) instead of the iShares S&amp;P/TSX Capped Composite Index ETF. Consumers that previously relied on this adapter to resolve non-ETF instrument metadata must migrate to a different endpoint or adapter; the adapter's role in the etfwealthiq consumer is ETF-focused so this is a clean scope narrowing, not a feature loss.
- `TwelveDataPriceBarAdapter` and `TwelveDataInstrumentMetadataAdapter` now append `&mic_code={Exchange}` to every outgoing request whose `PriceHistoryRequest.Exchange` / `InstrumentMetadataRequest.Exchange` is non-null. The MIC string is the enum member's name verbatim — after the 1.1.0 `ExchangeCode` ISO-realignment rename, every member name IS the ISO 10383 MIC, so no translation layer is needed. This disambiguates symbols that trade on multiple venues (e.g. `XIC` on both `XTSE` and `NEOE` Canadian venues) and is what makes the bulk of TwelveData's Canadian ETF catalog resolvable — the CA research smoke-test for `balanced-growth-ca` went from 5/18 CA tickers resolving to **18/18 CA tickers resolving** after this change. Venue-neutral requests (`Exchange = null`) are unaffected — no `mic_code` param is emitted and TwelveData's default selection applies.
- `TwelveDataPriceBarAdapter.FetchAsync` now paginates backward from `request.Range.To` when a single page cannot cover the requested range. Twelve Data's `/time_series` endpoint hard-caps responses at 5000 bars per call (validated range `[1, 5000]` regardless of subscription tier, verified by direct API probe on a paid account), so a 25-year CA-equity request (e.g. XIC from 2001 onward, ~6300 trading days) previously received only the most-recent 5000 bars (2008-2026) and the consumer's `CoverageResponseEvaluator` rejected the partial response — producing a "Benchmark variance is zero" failure cascade across every CA blueprint that started pre-2008. The paging loop walks backward one page at a time, stopping when the oldest bar reaches `request.Range.From`, the page came back short (server exhausted), or a safety cap of 20 pages × 5000 bars = 100 000 bars is hit. Pages are merged, de-duplicated on date, and sorted ascending before return — bars were previously emitted in descending date order, causing consumers that treated `bars[^1].Date` as "latest" to silently read the oldest date instead.

### Changed

- The kernel's `CurrencyCode` enum was removed in `Boutquin.MarketData.Abstractions` (currency unification); `BankOfCanadaFxAdapter`'s internal CAD/USD series map now keys on the ecosystem-wide `Boutquin.Domain.Currency` enum (`Currency.USD` / `Currency.CAD`) instead. Both enums share identical ISO 4217 numeric backing, so adapter behaviour is unchanged — the swap is confined to a `private static readonly` dictionary and touches no public API surface (no source or binary break for adapter consumers). This RC requires `Boutquin.Domain` `1.0.0` and `Boutquin.MarketData.*` `2.0.0-rc.20261027.4`.
- `TiingoPriceBarAdapter.CanHandle` and `TiingoInstrumentMetadataAdapter.CanHandle` now return `false` when the request's `Exchange` hint names a venue outside Tiingo's coverage (Tiingo supports `{ XNYS, XNAS }` — US equities and ETFs only). Requests with `Exchange = null` remain venue-neutral and continue to be handled as before. Closes the 2026-04-19 CA research failure mode where bare 3-letter symbols that collide across venues (`XIC` = iShares S&P/TSX Capped Composite on TSX vs. Cimarex Energy on US markets) were silently served with US data regardless of intent.
- `TwelveDataPriceBarAdapter.CanHandle` and `TwelveDataInstrumentMetadataAdapter.CanHandle` now return `false` when the request's `Exchange` hint names a venue outside the adapter's declared support set. TwelveData supports `{ XTSE, NEOE, XNYS, XNAS }` — the four venues the current consumer (etfwealthiq) declares. TwelveData covers more global venues commercially; extending the set is an opt-in change so routing precedence never changes silently under a downstream consumer. `Exchange = null` requests are unaffected.
- All four changes require the 1.1.0 `Boutquin.MarketData.Abstractions` package, which adds `ExchangeCode? Exchange` to every request record.

### Fixed

- `TwelveDataPriceBarAdapter` now returns a range's last bar. It sent `end_date` as a bare date, which Twelve Data reads as that day's midnight, and its daily bars since about 2016 are stamped later in the day. So a request ending on a trading day silently stopped at the previous trading day: XIC/XTSE requested through 2026-09-21 came back through 2026-09-18. When a range needed paging, each page after the first also lost its last day. Older bars carry a midnight timestamp, so ranges ending before about 2012 were unaffected, which is why the paging tests never caught it. `end_date` now carries the end of the day (`yyyy-MM-dd 23:59:59`), matching the request's documented inclusive range (live probe 2026-09-25).
- `BankOfEnglandSoniaAdapter` now returns SONIA fixings. Three defects stacked so that the adapter had never returned an observation with default options, each masked by the next (all verified against the live IADB on 2026-09-21): (1) the default `BankOfEnglandOptions.SoniaSeriesCode`, `IUDSNKY`, is not an IADB series — the Bank answers it with "Invalid series code value supplied"; the SONIA series is `IUDSOIA` ("Daily Sterling overnight index average (SONIA) rate", history from 1997-01-02), now the default. (2) The request omitted `UsingCodes=Y`, without which the IADB does not read `SeriesCodes` as series codes and redirects to its HTML error page even for a valid code; the parameter is now sent. (3) The parser expected quoted two-digit-year dates (`"02 Jan 24"`) while the export carries unquoted `02 Jan 2024` (`dd MMM yyyy`, CRLF), so even a correct response parsed to zero rows; the parser now reads the wire format. Because the IADB serves its error page as HTTP 200 HTML, the adapter previously parsed that page as CSV and reported `NO_OBSERVATIONS` (plus one `UNEXPECTED_GAP` per business day) rather than a failure, which is how the defect stayed invisible; a body that does not start with the `DATE,` header is now reported as a `SCHEMA_MISMATCH` error with no gap noise. Every unit fixture and the integration golden had been hand-written in the parser's imagined format; they are replaced with captured IADB responses, and new tests pin the exact request URL. Values are unchanged in meaning (percent → decimal rate).
- `BankOfCanadaYieldCurveAdapter` now fetches the Canadian zero-coupon yield curve from the source that actually publishes it. Earlier versions requested the Valet observation group named by `BankOfCanadaOptions.GroupName` (default `BD.CDN.ZERO`); Valet has no zero-coupon group under that or any other name — the request answers HTTP 404 `Group BD.CDN.ZERO not found` (verified against the live API and its 2,538-entry group list on 2026-09-21) — so with default options the adapter failed every request with a `FETCH_FAILED` issue and never returned a quote. The Bank publishes the curve as the CSV download behind its "Yield curves for zero-coupon bonds" page (`https://www.bankofcanada.ca/stats/results/csv?lookupPage=lookup_yield_curve.php&dFrom=…&dTo=…`): a `Date` column plus 120 `ZCnnnYR` term columns from 0.25 to 30 years, rates already in decimal form, `na` for days without a curve, refreshed weekly with a lag of about two weeks. The adapter now requests a 30-day window ending on `AsOfDate` (`BankOfCanadaYieldCurveAdapter.LookbackDays`), serves the latest row that carries a numeric value, skips all-`na` holiday rows, and labels each term by tenor — whole years as `1Y`…`30Y`, other terms in months (`3M`, `6M`, `9M`, `15M`, …) — so the `BOC-ZERO` curve recipe in `Boutquin.Curves` resolves its 3M–30Y nodes without translation. A request inside the publication lag rolls back to the most recent published curve with a `DATE_ROLLBACK` warning naming the date served; a window with no curve at all reports `EMPTY_OBSERVATIONS`, and a non-CSV response reports `SCHEMA_MISMATCH`. Provenance freshness is `Delayed` (previously `EndOfDay`). New option `BankOfCanadaOptions.YieldCurveLookupUrl` (default `https://www.bankofcanada.ca/stats/results/csv`) replaces `GroupName`, which is now `[Obsolete]` and has no effect; it is retained so existing configuration bindings keep compiling. The lookup endpoint is the Bank's own download link but is not part of the documented Valet API. The FX and CORRA adapters are unchanged. Unit tests cover the real CSV shape (trailing empty column, `na` cells, holiday rows, header-only responses), the tenor mapping, rollback, and pin the exact request URL; the integration golden is a real response captured from the endpoint.
- `EcbOptions.EstrSeriesKey` now defaults to `EST/B.EU000A2X2A25.WT`, the ECB Data Portal series titled "Euro short-term rate" (volume-weighted trimmed mean rate). The previous default, `FM/B.U2.EUR.4F.KR.DFR.LEV`, is the Deposit Facility Rate "date of changes" series: the ECB serves it with HTTP 200, so `EcbEstrAdapter` raised no error and returned deposit-facility levels — dated only on policy-change days, and an empty response for any range without one — labelled as €STR fixings. Consumers that read `StandardBenchmarks.EurEstr` from this adapter received the wrong rate. The CSV parsing is unchanged (`TIME_PERIOD` and `OBS_VALUE` sit before the quoted, comma-bearing `COMMENT_TS` attribute in the live response, so the plain comma split still lands on the right columns — now covered by a test); an explicit `EstrSeriesKey` override is unaffected. The €STR series starts 2019-10-01. Unit tests pin the exact request URL, and the integration golden is now a real `csvdata` response for 2024-01-02..04 (3.906 / 3.904 / 3.902) rather than a hand-written file carrying the wrong series id.
- `FrankfurterOptions.BaseUrl` now defaults to `https://api.frankfurter.dev/v1`. The previous default, `https://api.frankfurter.dev`, omitted the API version segment: the adapter appends the time-series path directly to `BaseUrl`, and the service answers the resulting unversioned URL (`https://api.frankfurter.dev/{from}..{to}?base=…&symbols=…`) with HTTP 404 while serving the same path under `/v1` with HTTP 200 (verified against the live service on 2026-09-21). With default options, `FrankfurterFxAdapter` therefore failed every pair with a `FETCH_FAILED` issue and returned no rates, so a pipeline with a fallback FX source silently served that source instead and never received ECB reference rates — for USD/CAD that meant history starting at the Bank of Canada `FXUSDCAD` series' 2017-01-03 rather than the ECB reference rates' 1999-01-04. The adapter's path construction and response parsing are unchanged — only the default moved — so an existing `BaseUrl` override that already includes the version segment stays correct, and an override pointing at a self-hosted instance is unaffected. New unit tests pin the exact URL the adapter issues (default and overridden `BaseUrl`), because the existing tests stubbed the transport on a URL substring that matched the dead endpoint as readily as the live one.

## [1.0.1] — 2026-04-17

## [1.0.0] — 2026-04-17

First public release. Boutquin.MarketData.Adapter ships eleven standalone NuGet packages — one per data source — each implementing `IDataSourceAdapter<TRequest, TRecord>` from `Boutquin.MarketData.Abstractions` and self-registering via an `AddMarketData*()` extension on `IServiceCollection`. The kernel (`Boutquin.MarketData`) handles transport, caching, normalization, and pipeline orchestration; the adapters handle provider-specific parsing, authentication, and URL construction only.

### Highlights

- **Eleven standalone packages, one dependency each.** Every adapter depends only on the kernel packages (`Abstractions`, `Transport`, `Storage`). No adapter depends on another adapter. Install only the packages you need; the DI composition assembles them at runtime via `IPrioritizedAdapter` ordering.
- **`DataDate` discipline.** Every adapter sets `DataProvenance.DataDate` to the actual business date of data served — not the wall-clock date of the fetch. When the actual date lags the requested date (T+1 publication, weekend gap, holiday), the adapter emits a `DataIssue` with `IssueCode.StaleData` so callers can distinguish a fresh observation from a carried-forward one.
- **Calendar-aware coverage.** `GapClassifier` and `AdapterCoverageHelper` in the shared package classify date-series gaps as expected (holidays, weekends, known publication lag) or unexpected (genuine missing data), feeding coverage metadata back into `DataProvenance` without false `StaleData` alerts on market-closed days.
- **Canonical-first.** Adapters emit typed records, not dictionaries. Provider-specific field names, casing quirks, and percent-vs-decimal conventions are resolved inside the adapter; the pipeline sees only `Bar`, `FxRate`, `ScalarObservation`, `YieldCurveQuote`, `FuturesSettlement`, `FactorObservation`, and `InstrumentMetadata`.
- **SSRF is a kernel concern, not an adapter concern.** Adapters never construct URLs from unvalidated external input; all HTTP dispatch flows through `ResilientHttpDataTransport`, which validates every URI before dispatch and blocks loopback, private-range, and cloud-metadata targets at the transport layer.

### Added

#### Shared Utilities (`Boutquin.MarketData.Adapter.Shared`)

- **`GapClassifier`** — classifies date-series gaps as expected (weekend, market holiday, known T+N publication lag) or unexpected (genuine missing observation). Uses kernel business-day calendars to determine which dates are expected to have no publication.
- **`AdapterCoverageHelper`** — aggregates per-partition gap classifications into a `CoverageComputation` instance and surfaces the result in `DataProvenance`, enabling pipelines to distinguish a full-coverage fetch from a partial one without inspecting individual records.

#### Equity and Instrument Data

- **`Boutquin.MarketData.Adapter.Tiingo`** — `TiingoPriceBarAdapter` producing split- and dividend-adjusted daily `Bar` records from the [Tiingo REST API](https://www.tiingo.com/documentation/general/overview); `TiingoInstrumentMetadataAdapter` producing `InstrumentMetadata`. Requires `TiingoOptions.ApiToken`; requests without a valid token receive HTTP 401. `AddMarketDataTiingo(opts => ...)` DI extension.

- **`Boutquin.MarketData.Adapter.TwelveData`** — `TwelveDataPriceBarAdapter` producing daily `Bar` records from the [Twelve Data API](https://twelvedata.com/docs) covering global equities, ETFs, and indices; `TwelveDataInstrumentMetadataAdapter` producing `InstrumentMetadata`. Requires `TwelveDataOptions.ApiKey`; requests without a valid key receive HTTP 401. Suitable as a fallback source alongside Tiingo via `IPrioritizedAdapter` ordering. `AddMarketDataTwelveData(opts => ...)` DI extension.

#### FX Rates

- **`Boutquin.MarketData.Adapter.Frankfurter`** — `FrankfurterFxAdapter` producing `FxRate` records from the [Frankfurter API](https://www.frankfurter.dev/) (ECB reference rates). Anonymous — no authentication required. Rates are published on TARGET business days only; requesting a date when the ECB did not publish returns the most recent prior rate with a `DataIssue`. `AddMarketDataFrankfurter()` DI extension.

#### Yield Curves

- **`Boutquin.MarketData.Adapter.UsTreasury`** — `UsTreasuryYieldAdapter` producing constant-maturity Treasury `YieldCurveQuote` records from the [US Treasury H.15 XML feed](https://home.treasury.gov/resource-center/data-chart-center/interest-rates/). Anonymous. Published on US federal government business days; weekend and holiday dates emit `DataIssue`. `AddMarketDataUsTreasury()` DI extension.

- **`Boutquin.MarketData.Adapter.BankOfCanada`** — three adapters sharing `BankOfCanadaOptions`: `BankOfCanadaYieldCurveAdapter` producing Canadian zero-coupon `YieldCurveQuote` records from the [Valet API](https://www.bankofcanada.ca/valet/docs) (configurable `GroupName`, default `BD.CDN.ZERO`); `BankOfCanadaFxAdapter` producing `FxRate`; `BankOfCanadaCorraAdapter` producing `ScalarObservation` for the CORRA overnight rate fixing. Anonymous. `AddMarketDataBankOfCanada()` DI extension.

#### Overnight Rate Fixings

- **`Boutquin.MarketData.Adapter.NewYorkFed`** — `NewYorkFedSofrAdapter` producing `ScalarObservation` for the SOFR overnight rate from the [NY Fed Markets API](https://markets.newyorkfed.org/static/docs/markets-api.html). Anonymous. SOFR is published T+1; requesting today's rate before publication returns the prior fixing with a `DataIssue`. Corresponds to `StandardBenchmarks.UsdSofr` in the kernel. `AddMarketDataNewYorkFed()` DI extension.

- **`Boutquin.MarketData.Adapter.BankOfEngland`** — `BankOfEnglandSoniaAdapter` producing `ScalarObservation` for the SONIA overnight rate from the [Bank of England IADB](https://www.bankofengland.co.uk/boeapps/database/). Anonymous. Default series code `IUDSNKY`. Corresponds to `StandardBenchmarks.GbpSonia`. `AddMarketDataBankOfEngland()` DI extension.

- **`Boutquin.MarketData.Adapter.Ecb`** — `EcbEstrAdapter` producing `ScalarObservation` for the Euro Short-Term Rate (ESTR / €STR) from the [ECB SDMX Data Service](https://data.ecb.europa.eu/help/api/data). Anonymous. Default SDMX series key `FM/B.U2.EUR.4F.KR.DFR.LEV`. Published on TARGET business days. Corresponds to `StandardBenchmarks.EurEstr`. `AddMarketDataEcb()` DI extension.

#### Factor Data

- **`Boutquin.MarketData.Adapter.FamaFrench`** — `FamaFrenchFactorAdapter` producing `FactorObservation` records from the [Ken French Data Library](https://mba.tuck.dartmouth.edu/pages/faculty/ken.french/data_library.html) (Dartmouth FTP endpoint). Anonymous. Downloads compressed CSV files and handles the canonical current file format for three-factor, five-factor, and momentum datasets. `AddMarketDataFamaFrench()` DI extension.

#### Futures Settlements

- **`Boutquin.MarketData.Adapter.Cme`** — `CmeSettlementAdapter` producing `FuturesSettlement` records by parsing CME Group daily settlement CSV exports from a local directory (no network call). `CmeOptions.SettlementDirectory` and `CmeOptions.FilePattern` (default `*.csv`) configure the source path. CME settlement files must be obtained separately from the CME Group or a licensed data vendor. `AddMarketDataCme(opts => ...)` DI extension.
